# Documentation conventions

- Keep reference documents useful and navigable: clear headings, concise explanations, and links to authoritative source material.
- The ADRs document decisions and trade-offs; do not rewrite historical decisions merely to make them match a later implementation.
- Keep specifications, implementation evidence, and release instructions distinguishable from one another.
- Catalog verification and metadata reuse conclusions must be sourced. Distinguish factual reference data from original expression and conditional database rights. Do not infer permission from attribution or the MIT code license, or assert that missing permission proves infringement.
- Release documentation must match the actual Pages workflow: merges to `main` can publish automatically; no release authorization gate is configured.
