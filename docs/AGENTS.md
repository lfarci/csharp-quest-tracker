# Documentation conventions

- Keep reference documents useful and navigable: clear headings, concise explanations, and links to authoritative source material.
- The ADRs document decisions and trade-offs; do not rewrite historical decisions merely to make them match a later implementation.
- Keep specifications, implementation evidence, and release instructions distinguishable from one another.
- Catalog verification and metadata reuse conclusions must be sourced. Do not infer permission to use book-derived metadata from attribution or the MIT code license.
- Release documentation must match the actual Pages workflow and its authorization gates.
